# EchoLink protocol

EchoLink is the direct LAN protocol between the Echo360 Android app and the future EchoCore service running on the Xbox 360.

The first milestone is intentionally tiny: prove that Echo-owned code on both sides can establish one TCP connection and complete `PING -> PONG` without Aurora FTP, FTPdll, NOVA or a PC/Termux relay.

## Transport

- TCP over the local network.
- Default port: `36000`.
- Network byte order (big-endian) for multi-byte integers.
- The bootstrap protocol is LAN-only and unauthenticated. It MUST NOT expose filesystem writes, launch, reboot, memory, keys or privileged commands until pairing/authentication is added.

## Frame header — v1

Every frame starts with exactly 16 bytes:

| Offset | Size | Field | v1 |
| ---: | ---: | --- | --- |
| 0 | 4 | magic | ASCII `ECHO` / `0x4543484F` |
| 4 | 1 | version | `1` |
| 5 | 1 | type | command/response type |
| 6 | 2 | flags | `0` unless defined later |
| 8 | 4 | payloadLength | unsigned logical length, bounded before allocation |
| 12 | 4 | requestId | echoed by the response |

Control payloads are limited to 1 MiB in v1. Large file transfer will use dedicated bounded data frames/chunks rather than raising this control limit.

## Bootstrap frame types

- `0x01 PING`
- `0x02 PONG`
- `0x7F ERROR` reserved for structured protocol errors

### PING

Payload: one opaque 64-bit nonce generated by the client.

### PONG

The server MUST return:

- the same `requestId`;
- the exact same nonce payload;
- protocol version `1`.

This lets the client reject stale or cross-wired responses and measure round-trip latency.

## Fail-closed rules

The bootstrap server must close the connection on:

- bad magic;
- unsupported version;
- unknown frame type;
- oversized payload length;
- incomplete frame;
- malformed command payload.

No bootstrap command is allowed to modify the console.

## Evolution

Planned additive commands after hardware proof:

1. read-only device/list/stat;
2. pairing/authentication;
3. chunked upload into a safe temporary path;
4. verify + finalize;
5. telemetry/session/Doctor APIs;
6. privileged operations only after explicit security review.

The protocol is versioned so Android can keep NOVA/Aurora FTP/FTPdll as fallbacks when EchoCore is absent or incompatible.
